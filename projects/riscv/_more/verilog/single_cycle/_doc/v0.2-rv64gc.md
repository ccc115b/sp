# single_cycle v0.2 — RV64IM + Zicsr + Zifencei 單週期處理器

## 概述

在 v0.1 (RV64I) 基礎上擴充至 **RV64GC** 子集（M-extension + Zicsr + Zifencei）。單一檔案 `rv64i_cpu.v`（~407 行），支援 Icarus Verilog 與 Verilator 驗證。所有指令仍維持單週期完成。

## 建置與執行

```bash
cd single_cycle
./test.sh
```

或手動：

```bash
iverilog -o single_cycle_tb -g2012 rv64i_cpu.v tb_rv64i.v
vvp single_cycle_tb
```

## v0.2 新增功能

| 類別 | 指令/暫存器 | 詳細 |
|------|-------------|------|
| **M-extension** | MUL / MULH / MULHSU / MULHU | 整數乘法（64×64→128 bit） |
| | DIV / DIVU | 整數除法（overflow 傳回特殊值） |
| | REM / REMU | 整數取餘數 |
| **Zicsr** | CSRRW / CSRRS / CSRRC | 透過 `rs1` 存取 CSR |
| | CSRRWI / CSRRSI / CSRRCI | 透過 5-bit 立即數存取 CSR |
| | mcycle / minstret | 自動遞增的效能計數器 |
| | mstatus / mtvec | 機態控制與 trap 向量 |
| **Zifencei** | FENCE.I | 視為 NOP（`0x0000100f`） |

## 架構新增

### ALU Datapath — M-extension

```
mul_full_s  = $signed(alu_a) * $signed(alu_b)   → 128-bit signed
mul_full_u  = alu_a * alu_b                      → 128-bit unsigned
mul_full_su = $signed(alu_a) * {1'b0, alu_b}    → 128-bit mixed

ALU_MUL:   alu_result = mul_full_s[63:0]
ALU_MULH:  alu_result = mul_full_s[127:64]  (若 funct3==3'b010 → su)
ALU_MULHU: alu_result = mul_full_u[127:64]

ALU_DIV:   有號除法（overflow: x[rd]=INT64_MIN）
ALU_DIVU:  無號除法（divide-by-zero: x[rd]=~0）
```

### CSR 檔案系統

```
mcycle   (0xB00): posedge 自動 +1，可透過 CSR 指令寫入
minstret (0xB02): posedge 自動 +1，可透過 CSR 指令寫入
mstatus  (0x300): 機態狀態暫存器
mtvec    (0x305): trap 向量基底位址
```

CSR 讀取為組合邏輯（與 ALU 結果平行計算），寫入在 posedge clk 完成。

### 控制單元擴充

opcode `0x73` (SYSTEM) 新增處理：
- `funct3[2] == 1` → `csr_imm` 訊號使用 `imm_z` 作為寫入值
- CSRRW/CSRRWI (`funct3=001/101`) → 總是寫入
- CSRRS/CSRRSI (`funct3=010/110`) → rs1/uimm≠0 時寫入
- CSRRC/CSRRCI (`funct3=011/111`) → rs1/uimm≠0 時寫入

Write-back 多工器新增 `csr_rdata` 路徑（優先於其他來源）。

### ALU Control 擴充

R-type（`opcode=0x33`）的 `funct7=0x01` 區段新增：
- `funct3=000` → MUL（ALU_MUL）
- `funct3=001` → MULH（ALU_MULH）
- `funct3=010` → MULHSU（ALU_MULH + funct3 條件分支）
- `funct3=011` → MULHU（ALU_MULHU）
- `funct3=100` → DIV（ALU_DIV + funct3 條件分支）
- `funct3=101` → DIVU（ALU_DIVU）
- `funct3=110` → REM（ALU_DIV + funct3 條件分支）
- `funct3=111` → REMU（ALU_DIVU + funct3 條件分支）

## 設計決策

### M-extension 除法
- 在單週期內完成（合成時面積大，但模擬無問題）
- Overflow（`DIV` x[rs1]=INT64_MIN, x[rs2]=-1）回傳 INT64_MIN
- Divide-by-zero 回傳 `~0`（all-ones），符合 RISC-V 規格

### ALU 控制編碼
`ALU_MULH` 與 `ALU_DIV` 的控制碼由內部 `funct3` 條件分支決定 REM 與 MULHSU 的細微差異，節省 ALU 控制訊號位元。

### CSR 寫入規則
嚴格遵循 RISC-V 規格：
- CSRRS/CSRRSI 在 `rs1/uimm == 0` 時**不寫入**（唯讀）
- CSRRC/CSRRC 在 `rs1/uimm == 0` 時**不寫入**

### FENCE.I
視為 NOP（`0x0000100f`），在支援快取之前無實際效果。

## 未支援 (vs. 完整 RV64GC)

- **A extension** (LR/SC / AMO swap/add/xor/and/or/min/max) — 需 atomic 操作
- **F/D extension** (單/雙精度浮點) — 需 FPU
- **C extension** (壓縮指令) — 需 16-bit 指令解碼器
- **S-mode / U-mode** — 需頁表與異常處理機制
- **Zbkb/Zbkc/Zbkx** (位元操作擴充)
