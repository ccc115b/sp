# single_cycle v0.4 — mini-riscv-os

讓單週期 CPU 能執行 `riscv/mini-riscv-os/` 下的多工 OS（Preemptive Multitasking with Timer Interrupt + Atomic Mutex）。

## mini-riscv-os 分析

### 目標環境

| 項目 | 內容 |
|------|------|
| ISA | RV32IMA_Zicsr |
| ABI | ilp32 (32-bit) |
| Linker | 0x80000000 起，128MB RAM |
| 建置 | Rust staticlib + start.o + sys.o → os.elf |

### 硬體需求

| 區塊 | 位址範圍 | 需求 |
|------|---------|------|
| 程式/資料 RAM | 0x80000000+ | 讀寫 (imem + dmem) |
| UART (16550) | 0x10000000–0x10000007 | 寫 THR (=putchar)，讀 LSR 檢查 BUSY |
| CLINT | 0x02000000–0x0200FFFF | mtime (0x0200BFF8)，mtimecmp per-hart (0x02004000+) |

### 用到但目前 CPU 不支援的功能

| 功能 | 使用位置 | 缺口 |
|------|---------|------|
| `mret` | sys.s:129 (`csrw mepc, a1`) 後返回 | 無 mret 解碼 |
| `mscratch` CSR | sys.s 多處 csrrw | 無此 CSR |
| `mie` CSR | os_code.rs `w_mie()` | 無此 CSR |
| `wfi` | start.s:17 | 無解碼 (可 NOP) |
| UART MMIO | os_code.rs `putc` 寫 `0x10000000` | 無 MMIO 機制 |
| CLINT MMIO | os_code.rs `get_mtime`/`set_mtimecmp` | 無 MMIO 計時器 |
| Timer 中斷 | CLINT mtime > mtimecmp → 跳 mtvec | 無中斷管線 |
| `lr.w`/`sc.w` | AtomicI32.compare_exchange (A-ext) | 無 A-extension |
| 32-bit 運算 | LW/SW, slli 32-bit, addiw | 需確認相容性 |

### 不須修改的部分 (已支援)

- RV32I 基礎指令：ADDI, ADD, SUB, XOR, OR, AND, SLT/SLTU, LW/LH/LB, SW/SH/SB, BEQ/BNE/BLT/BLTU/BGE/BGEU, LUI, AUIPC, JAL, JALR
- RV64I 延伸指令 (不被 OS 使用，但無害)：LD/SD, ADDIW, SLLIW, SRLIW, SRAIW, ADDW, SUBW, SLLW, SRLW, SRAW
- RVC 壓縮指令
- Zicsr 部分：mstatus (MIE 位元以外), mtvec, mepc, mcause, mcycle, minstret (目前 64-bit；OS 不讀它們)
- M-extension：MUL, DIVU, MULH (OS 未用但無害)

## 實作項目

### 1. 記憶體映射改造

**現狀**：imem 從 `$readmemh` 載入到位址 0，dmem 從 alu_result[12:0] 索引 (8KB)。

**目標**：
- 程式在位址 `0x80000000`，而非 `0x00000000`
- dmem 用完整位址（至少低 18-bit）或分頁映射

**做法**：

```
imem 基底 = 0x80000000
dmem 基底 = 0x80010000 (或其他不重疊位置)
UART 區域 = 0x10000000–0x1000000F
CLINT 區域 = 0x02000000–0x0200FFFF
```

`imem_addr = (pc >= 0x80000000) ? pc - 32'h80000000 : pc`
`dmem_addr_s = (alu_result >= 0x80000000) ? alu_result - 32'h80000000 : ...` — 但需保留低位 MMIO 區。

**建議方案**：將 imem 容量擴至 `[0:16383]` (16K×32-bit = 64KB)，直接使用 `{alu_result[15:0]}` 為 dmem 索引，MMIO 區獨立處理：

```verilog
wire [15:0] imem_idx = pc[15:0];
wire [15:0] dmem_idx = alu_result[16:1];  // 8-bit 寬度... 待細化
```

> 細節待決定。關鍵是 os.elf 的 .text 在 0x80000000+，.data/.bss 在 0x80000000+，需保證皆可讀寫。

### 2. mret 指令

**編碼**：`funct12=0x302, opcode=0x73` → `0x30200073`

**行為**：
```
if (mstatus.MPP == 3) // M-mode
    pc = mepc;
    mstatus.MIE = mstatus.MPIE;
    mstatus.MPIE = 1;
    // (單週期可簡化)
```

**實作**：
```verilog
wire is_mret = !is_compressed && opcode == 7'b1110011 && funct3 == 3'b000 && funct12 == 12'h302;

always @(posedge clk) begin
    if (is_mret) begin
        pc <= mepc;
        mstatus[3] <= mstatus[7]; // MIE <= MPIE
        mstatus[7] <= 1'b1;       // MPIE <= 1
    end
end
```

### 3. CSR 擴充：mscratch, mie

**mscratch (0x340)**：通用暫存，timer handler 用於保存暫存器。

**mie (0x304)**：Machine Interrupt Enable。
```
bit 7: MTIE — Machine Timer Interrupt Enable
```

**實作**：新增兩個 64-bit reg，在 CSR 讀/寫路徑中加入。

### 4. A-extension：lr.w / sc.w

mini-riscv-os 透過 `AtomicI32::compare_exchange` 使用 atomic，編譯後產生 `lr.w` / `sc.w`。

**lr.w (Load Reserved)**：
```
opcode=0x2F, funct3=010, funct5=00010
rd = M[rs1] (32-bit sign-extended)
reservation_set(rs1)
```

**sc.w (Store Conditional)**：
```
opcode=0x2F, funct3=010, funct5=00011
if (reservation_valid(rs1))
    M[rs1] = rs2; rd = 0;
else
    rd = 1;
```

**單核簡化**：單週期 CPU 無需真正的 reservation。可實作為：
- `lr.w`：直接 load 32-bit → rd
- `sc.w`：直接 store 32-bit，rd = 0 (always succeed)

但需注意 `sc.w` 的 `rs1` 必須與 `lr.w` 的 `rs1` 一致，且中間無其它 store 到同一位址。在單核無 DMA 情境下永遠成功。

**實作**：
```verilog
// Atomic opcodes in opcode 0x2F (0b0101111)
case (funct5)
    5'b00010: begin // lr.w
        mem_width = 3'b010; // 32-bit load
        alu_src_a = 1'b0; alu_src_b = 2'b01; // base + 0
        reg_src = 2'b01; // mem_rdata_word
        reg_write = 1'b1;
    end
    5'b00011: begin // sc.w
        mem_write = 1'b1;
        mem_width = 3'b010; // 32-bit store
        alu_src_a = 1'b0; alu_src_b = 2'b01;
        reg_write = 1'b1;
        // rd = 0 (success) — hardwire
    end
endcase
```

### 5. Timer 中斷模擬

CLINT 提供兩個 memory-mapped 暫存器：
- `mtime` (0x0200BFF8)：64-bit 計數器，持續增加
- `mtimecmp` (0x02004000 + 4*hart)：64-bit，當 mtime >= mtimecmp 時觸發 MTIP

**實作方案**：

在 testbench 中：
- 每次 cycle 增加 `clint_mtime`（64-bit counter in CPU）
- 每次 cycle 檢查 `mtime >= mtimecmp`
- 若 MTIP 未處理且 `mie.MTIE=1`，觸發中斷：
  - `mcause <= 0x8000000000000007` (timer interrupt, top bit set)
  - `mepc <= pc`
  - `mstatus.MPIE <= mstatus.MIE`
  - `mstatus.MIE <= 0`
  - `pc <= mtvec`

在 CPU 中：
- 新增 `clint_mtime` reg (64-bit)
- 新增 `clint_mtimecmp` reg (64-bit per hart, 至少 hart0)
- MMIO 寫 `0x02004000` 更新 mtimecmp
- MMIO 讀 `0x0200BFF8` 返回 mtime

### 6. UART MMIO

mini-riscv-os 的 `putc`：
```rust
while (*UART_LSR & 0x40) == 0 {}  // 等 THR empty
UART_THR.write_volatile(c);       // 寫字元
```

**實作**：
- UART 基底 `0x10000000`
- `THR (+0x00)`：寫入 = 輸出字元；讀取 = 0 (無輸入)
- `LSR (+0x05)`：讀取 = `0x60` (THR empty + TEMT)，永遠 ready
- MMIO 位於低位址 (`< 0x80000000`)，需從 ALU result 直接判斷

**做法**：
```verilog
if (mem_write && alu_result >= 32'h10000000 && alu_result < 32'h10000010) begin
    if (alu_result[7:0] == 8'h00) // THR
        $write("%c", rf_rdata2[7:0]);
end else if (mem_write && alu_result >= 32'h80000000) begin
    // 一般 dmem write
end
```

讀取：
```verilog
if (alu_result >= 32'h10000000 && alu_result < 32'h10000010) begin
    case (alu_result[7:0])
        8'h00: mem_rdata_word = 0;             // RHR (無輸入)
        8'h05: mem_rdata_word = 8'h60;          // LSR (THR empty)
        default: mem_rdata_word = 0;
    endcase
end else if (alu_result >= 32'h80000000) begin
    // 一般 dmem read
end
```

### 7. wfi 指令

**編碼**：`funct12=0x105, opcode=0x73` → `0x10500073`

**行為**：Wait For Interrupt — 暫停執行直到有中斷。

**實作**：在單週期 CPU 中可直接當成 NOP。無中斷時 `wfi` 會導致 timeout，但可先跳過 (hart0 永遠不會執行到 wfi，只有 hart 1-3 會 parking)。

```verilog
wire is_wfi = !is_compressed && opcode == 7'b1110011 && funct3 == 3'b000 && funct12 == 12'h105;
// 解碼時不做任何操作 = NOP
```

### 8. 中斷處理管線

需在每個 cycle 的 posedge 前檢查：

```verilog
wire timer_irq = mie[7] && clint_mtime >= clint_mtimecmp;
wire has_interrupt = timer_irq && !is_ecall; // 避免中斷巢套

always @(posedge clk) begin
    if (has_interrupt && !is_mret) begin
        mepc   <= next_pc;  // 保存下一條指令位址 (或當前 pc？RISC-V 規範留給 mtvec)
        mcause <= 64'h8000000000000007;
        mstatus[7] <= mstatus[3]; // MPIE <= MIE
        mstatus[3] <= 1'b0;      // MIE <= 0
        pc <= mtvec;
    end else if (is_mret) begin
        pc <= mepc;
        mstatus[3] <= mstatus[7]; // MIE <= MPIE
        mstatus[7] <= 1'b1;       // MPIE <= 1
    end else begin
        pc <= next_pc;
    end
end
```

> 注意：中斷應在指令完成時 (writeback 後) 才觸發。單週期架構中，每個 cycle 是一條完整指令，可在 posedge 同時處理中斷與指令完成。

### 9. 多 hart 支援

mini-riscv-os 支援 `-smp 4`，但執行時只有 hart 0 做事，其餘在 `wfi` 迴圈。

**簡化**：只執行 hart 0，不實作多 hart。但需確保 `csrr mhartid` 回傳 0，讓其他 hart 的 code path 不會被跑到。
