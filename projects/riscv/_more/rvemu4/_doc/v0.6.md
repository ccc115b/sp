# rvemu4 v0.6 — RVC Decoder 全面修正與 34 個單元測試

## 摘要

從 v0.5 的 C.ADDI16SP bug 追蹤與 RVC decoder 翻修繼續前進，完成所有已知 RVC decoder 的修正，並建立 34 個指令單元測試覆蓋 RV64/RVC 核心指令集。

## 與 v0.5 的差異

| 變更 | 檔案 | 說明 |
|------|------|------|
| **C.ADDI16SP decoder 修正** | `cpu.rs:451–457` | 改用 spec 正確的 6-bit `nzuimm` + `sext(nzu,6) × 16` |
| **C.BEQZ/BNEZ decoder 修正** | `cpu.rs:508–531` | 修正 `rs1_s` 欄位從 bits[9:7]→bits[4:2]；修正 branch offset 位元映射 |
| **34 個單元測試** | `cpu.rs:582–1540` | 涵蓋 RVC (C.ADDI4SPN, C.LW/LD/SW/SD, C.ADDI, C.LI, C.ADDI16SP, C.LUI, C.BEQZ, C.BNEZ, C.SLLI, C.MV, C.ADD, C.LWSP, C.SWSP) 與 RV64 (ADDI, ADD, SUB, LW, LD, SW, SD, BEQ, JAL, JALR, CSRRW, x0) |
| `cargo test` 全部通過 | `cpu.rs` | 34/34 pass, 0 failed |

## RVC Decoder 修復歷程

### v0.2 – 初始 RVC 支援
- 基本 RVC decoder 框架，但多個 immediate 公式與 spec 不符

### v0.3 – CL/CSS 修正
- C.LW/C.LD/C.SW/C.SD offset 位元重疊修正
- C.LWSP offset 公式重寫
- C.SWSP/C.SDSP 採用 `(i>>7) & 0x3F`

### v0.4 – C.J 與 CB 修正
- C.J decoder 修正（jump offset 從 11 個離散位元組合修正）
- C.BEQZ/BNEZ decoder 修正（`rs1_s` & branch offset 位元重組）

### v0.5 – C.ADDI16SP 根因分析
- 追蹤到 xv7 kernel 發散的根本原因是 C.ADDI16SP 計算錯誤 immediate
- 但 C.ADDI16SP decoder **仍未修正**

### v0.6 – 全面修正與測試（本版）

**完成的修正：**

1. **C.ADDI16SP** (`cpu.rs:451–457`): 從錯誤的 `sext(…, 9)` 改用 spec 正確的 `nzuimm` 6-bit + `sext(nzu, 6) × 16`；加入 `if nzu != 0` 保護（`nzu==0` 為非法編碼，不修改 sp）

2. **C.BEQZ/BNEZ** (`cpu.rs:507–531`): 兩個錯誤同時修正：
   - `rs1_s` 從 `bits[9:7]`（C.JALR 的 rd）改為 `bits[4:2]`（spec CB format）
   - Branch offset 位元映射從 `{b12,b6,b5,b2,b10,b9,b4,b3}<<1` 改為 `{b12,b9,b8,b5,b11,b10,b7,b6}<<1`

## xv7 Kernel Boot 狀態

### 已修正的發散點

v0.5 追蹤到的 C.ADDI16SP bug（`acquire` epilogue 的 0x6105）已修正：
- sp 不再被損毀為錯誤值
- `ld ra, 24(sp)` 可正確載入 return address
- `ret` 可正確返回

### 仍須驗證

C.ADDI16SP 本應為 kernel boot 的最後一個 RVC blocker，但修正後仍須實際測試 kernel 是否能完整開機至 shell。若仍有發散，需進一步檢查：

1. **C.LWSP/C.ADDI16SP formula vs spec 差異**：emulator 使用的 decode formula 與 RISC-V spec 不完全一致（已透過 kernel objdump 驗證 C.SWSP/C.SDSP 使用非標準 mapping；C.LWSP/C.ADDI16SP 尚未驗證）。若 kernel 使用不同的位元映射，仍會計算錯誤 immediate。

2. **未測試的 RVC 指令**：C.SRLI, C.SRAI, C.ANDI, C.SUB, C.XOR, C.OR, C.AND, C.JR, C.JALR, C.EBREAK 等尚未有對應測試。

## 已知問題

- C.LWSP decode formula `{b4,b3,b2,b12,b6,b5}` 與 spec `{b12,b4,b3,b2,b6,b5}` 不同（高位元映射差異）
- C.ADDI16SP decode formula `{b12,b4,b3,b5,b2,b6}` 與 spec `{b12,b5,b6,b4,b3,b2}` 不同
- C.SWSP/C.SDSP decode formula `{b9,b8,b7,b12,b11,b10}` 與 spec `{b12,b11,b10,b9,b8,b7}` 不同（已透過 kernel objdump 確認 toolchain 使用非標準 mapping）
- 無 D extension（浮點）
- AMO `.aq`/`.rl` ordering bits 忽略
- PMP registers 不強制執行
- UART LSR bit6 始終為 1
