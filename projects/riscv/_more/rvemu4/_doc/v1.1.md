# rvemu4 v1.1 規劃 — 獨立執行 ELF 程式

## 目標

讓 rvemu4 除了執行 xv6 等完整作業系統外，也能直接執行 RISC-V ELF 程式（如 `hello`、`factorial`、`fib`、`sum`）。輸入 `elf` 副檔名時自動切換至獨立執行模式。

## 背景

Compiler4 monorepo 下的 `rv4` crate 已支援此功能：透過 `#![no_std]` + `#![no_main]` 的 Rust 程式，以 `riscv64imac-unknown-none-elf` target 編譯成 `.o`（ET_REL）或 `.elf`（ET_EXEC），直接載入執行。其 ECALL 系統呼叫介面為：

| a7 | 功能 | 參數 |
|----|------|------|
| 0  | exit(code) | a0 = exit code |
| 1  | putchar(c) | a0 = 字元 |
| 2  | puts(ptr, len) | a0 = 記憶體位址, a1 = 長度 |

## 實作項目

### 1. ELF 載入支援（`src/elf.rs`）

現有 `load_elf` 載入時假定位址已含 `RAM_BASE`（如 xv6 連結於 `0x80000000`）。獨立程式連結於低位址（如 `0x10000`），因此需**加上 `RAM_BASE` 偏移**：

```rust
// 變更：載入時自動加 RAM_BASE
let load_addr = (paddr - RAM_BASE) as usize;  // 現有：直接複製到 ram[load_addr]
// 若 paddr < RAM_BASE，表示是獨立程式，使用：
let ram_idx = paddr as usize;
// 實際寫入 ram[ram_idx]，但預期 CPU 以 M-mode 直接存取時位址為 RAM_BASE + paddr
```

實作方式：讀取 ELF 時偵測 `paddr < RAM_BASE`，若成立則自動加上 `RAM_BASE` 再寫入 ram（如同 xv6 kernel 已含 RAM_BASE 時直接寫入）。entry 同理。

### 2. ELF 類型自動偵測（`src/main.rs`）

透過 ELF header e_type 與 program header paddr 判斷：

- `ET_EXEC` + paddr >= `0x80000000` → **kernel mode**（現有行為，S/M-mode）
- `ET_EXEC` + paddr < `0x80000000` → **standalone mode**（M-mode，ECALL 由模擬器攔截）
- `ET_REL`（relocatable `.o`）→ **standalone mode**（需實作重定位，類似 rv4 作法）

Main loop 變更：

```rust
let mode = if elf_type == "standalone" { RunMode::Standalone } else { RunMode::Kernel };
```

### 3. 重定位支援（`src/elf.rs`）

實作 ET_REL（relocatable `.o`）載入，包含：

- Section header 解析（`get_sections_64`）
- Symbol table 解析（`find_symtab_64`）
- RELA relocation 處理：`R_RISCV_HI20`、`R_RISCV_LO12_I`、`R_RISCV_LO12_S`、`R_RISCV_PCREL_HI20`、`R_RISCV_PCREL_LO12_I/S`、`R_RISCV_CALL`、`R_RISCV_BRANCH`、`R_RISCV_JAL`
- 動態決定 entry 點（尋找 `_start` symbol，否則 fallback 到 base address）

參考 `rv4/src/elf.rs` 實作。

### 4. ECALL 系統呼叫處理（`src/cpu.rs`）

新增 `ecall_mode` 旗標（enum 或 bool），決定 ECALL 行為：

- **Kernel mode**（預設）：現有行為 → trap to M-mode（mcause=11）→ xv6 處理
- **Standalone mode**：攔截 ECALL，實作三個 syscall：

  ```rust
  fn handle_ecall_standalone(&mut self) {
      match self.x[17] {  // a7
          0 => { exit_code = self.x[10] as i32; halt = true; }
          1 => { print!("{}", self.x[10] as u8 as char); pc += 4; }
          2 => {
              let addr = self.x[10]; // ptr in guest memory
              let len = self.x[11] as usize;
              // 透過 bus load8 讀取 guest 記憶體並輸出
              for i in 0..len {
                  if let Ok(c) = bus.load8(addr + i) { print!("{}", c as char); }
              }
              pc += 4;
          }
          _ => { halt = true; exit_code = 1; }
      }
  }
  ```

  注意 `puts` syscall 需從 **guest 實體位址**讀取字串，應使用 `Bus::load8`（現有，含 RAM_BASE offset）。

### 5. 新檔案與執行方式

```
./run.sh hello.elf          # standalone 模式
./run.sh factorial.elf
./run.sh -kernel kernel -drive disk    # kernel 模式（現有）
```

偵測邏輯：若命令列不含 `-kernel` 旗標，或 ELF 檔名以 `.o` 或 `.elf` 結尾且非 kernel ELF，則視為 standalone 模式。

### 6. 範例程式

於 `examples/` 目錄新增（或參考 `rv4/examples/`）：

- `hello.rs`：輸出 `"Hello, World!\n"`
- `fact.rs`：計算 `fact(10)` 並輸出
- `fib.rs`：計算 `fibonacci(20)` 並輸出
- `sum.rs`：計算 `sum(1..100)` 並輸出

編譯方式：

```bash
rustc --target riscv64imac-unknown-none-elf -C opt-level=z -C overflow-checks=off examples/hello.rs -o examples/hello.o
```

## 實作順序

1. ELF relocation（`src/elf.rs`）：移植 `rv4/src/elf.rs` 的 section reading + symbol table + RELA 處理
2. ELF 載入偏移：偵測 paddr < RAM_BASE 時自動加上 RAM_BASE
3. ECALL standalone handler（`src/cpu.rs`）
4. Main loop 模式切換（`src/main.rs`）
5. 範例程式 + 測試
6. `run.sh` / `debug.sh` 更新

## 風險

- **記憶體衝突**：獨立 ELF 常採用低位址（0x10000），與 xv6 kernel 重疊。需確保兩種模式擇一使用，kernel 模式下不載入低位址 ELF。
- **重定位實作正確性**：`PCREL_HI20` + `PCREL_LO12_I/S` 的 label 配對邏輯複雜，需對照 rv4 實作。
- **puts 的記憶體讀取**：需使用 guest memory 讀取（含 RAM_BASE offset），不可直接 dereference pointer。

## 預計變更範圍

| 檔案 | 變更 |
|------|------|
| `src/elf.rs` | 重寫：新增 section/symbol/relocation 支援；保留 kernel ELF 載入 |
| `src/cpu.rs` | 新增 `ecall_standalone` handler；新增 mode 旗標 |
| `src/main.rs` | 新增 ELF 類型偵測與模式切換 |
| `examples/*.rs` | 新增 4 個範例程式 |
| `run.sh`/`debug.sh` | 支援 `.o`/`.elf` 參數 |

## 不影響範圍

- 所有現有 131 個單元測試維持不變
- xv6 kernel 執行不受影響
- PLIC/CLINT/UART/VIRTIO 邏輯不變
