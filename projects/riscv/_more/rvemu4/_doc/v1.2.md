# rvemu4 v1.2 — 修正三個 RVC 解碼錯誤：C.ADDI4SPN / C.LWSP / C.SWSP，xv6-rust-octopos 完整開機

## 摘要

v1.1 的 octopos 核心開機至 `fs::init` 時因 superblock magic 比對失敗而卡死。經追查，根源為三個壓縮指令（RVC）的解碼器使用錯誤的位元對應公式，導致 `C.ADDI4SPN` 算出錯誤位址、`C.SWSP` 寫入錯誤記憶體位置。修復後 xv6-rust-octopos 可完整開機至 Shell，`ls`、`cat`、`echo` 等 POSIX 工具均可正常運作。

## 根因分析

### 問題 1：C.ADDI4SPN nzu 高位位元交換（q=0, f3=0）

C.ADDI4SPN 從 16 位元指令的 8 個分散位元組合出 8 位元 `nzu`（non-zero immediate）：
```
nzu = {b10, b9, b8, b7, b12, b11, b5, b6}
```
舊程式將 `b5` 放在 `b6` 前面：
```rust
(((i >> 5) & 1) << 1) | ((i >> 6) & 1)
```
應為：
```rust
(((i >> 6) & 1) << 1) | ((i >> 5) & 1)
```

**影響**：`sp + nzu*4` 計算錯誤。例如 `c.addi4spn x11, sp, 40`（指令 `0x1028`）：
- 舊：`nzu = 129` → `sp + 516`（錯誤）
- 新：`nzu = 10` → `sp + 40`（正確）

核心在 `kalloc::init` 階段即因錯誤位址而崩潰。

### 問題 2：C.LWSP immediate 位元順序錯誤（q=2, f3=2）

C.LWSP 從 bits[12] + bits[6:2] 組合出 6 位元 `uimm`，`offset = uimm << 2`。

CI 格式的六個分散位元（bit3, bit2, bit12, bit6, bit5, bit4）應對應到 uimm[5..0]，但舊程式使用了不同的順序 `{b4,b3,b2,b12,b6,b5}`：

```
正確：uimm = {b3, b2, b12, b6, b5, b4}
舊：  uimm = {b4, b3, b2, b12, b6, b5}
```

**影響**：所有 C.LWSP 的偏移計算錯誤。例如 `c.lwsp x1, 40(sp)`（指令 `0x50A2`）：
- 舊：`uimm = 5` → `sp + 20`（錯誤）
- 新：`uimm = 10` → `sp + 40`（正確）

### 問題 3：C.SWSP immediate 位元順序錯誤（q=2, f3=6）★ 致命

C.SWSP 從 bits[12:7] 組合出 6 位元 `uimm`，`offset = uimm << 2`。

CSS 格式的六個位元（bit8, bit7, bit12, bit11, bit10, bit9）應對應到 uimm[5..0]，但舊程式用了 `{b9,b8,b7,b12,b11,b10}`：

```
正確：uimm = {b8, b7, b12, b11, b10, b9}
舊：  uimm = {b9, b8, b7, b12, b11, b10}
```

**影響**：核心的 `buf.c` 透過 `C.SWSP` 寫入 buffer cache 時，因位址錯誤而破壞已讀取的 superblock 資料。這導致下列矛盾現象：
```
DEBUG1 magic=0x10203040    ← 第一次讀取正確
DEBUG4 m=0x0 f=0x10203040 eq=false  ← 第二次讀取已損毀
```
原因是核心先 `println!("magic={:#x}", sb.magic)`（成功），接著變數 `m = sb.magic`（此時資料已被錯誤的 C.SWSP 覆蓋）。

### CI/CSS 格式的關鍵發現

C.LWSP（word, shift=2）與 C.LDSP（double, shift=3）使用**完全相同的指令位元配置**，但由於 shift 不同，相同的 `uimm` 編碼值對應到不同的位元組偏移。因此同一個 immediate 位元在兩種指令中必須對應到 `uimm` 的不同位置：

| 位元 | C.LWSP (uimm index) | C.LDSP (uimm index) |
|------|---------------------|---------------------|
| b4   | 0 (LSB)            | 5 (MSB) |
| b5   | 1                  | 0 (LSB) |
| b6   | 2                  | 1 |
| b12  | 3                  | 2 |
| b2   | 4                  | 3 |
| b3   | 5 (MSB)            | 4 |

C.SWSP/C.SDSP 同理。這意味著 CI/CSS 格式的立即值解碼**必須依賴 funct3**，無法共用同一條公式。

## 測試驗證

所有修正均以 `riscv64-unknown-elf-as -march=rv64gc` 產生的編碼作為參考基準。對每個修正的指令測試了 7 組以上不同偏移值（4, 8, 16, 32, 40, 64, 128...），確認每位元位置正確對應。

## 終端機自動恢復

v1.1 在非正常退出（panic、`process::exit`、Ctrl-C）時會留下 terminal raw mode，使用者必須手動 `reset`。

v1.2 加入四層防護：
1. **`RawModeGuard`** — 包住 `run()` 的 Drop guard，panic/unwind 時自動恢復
2. **`libc::atexit`** — `process::exit`（如 Ctrl-A x）時觸發
3. **SIGINT handler** — Ctrl-C 時恢復
4. **明確復原** — `set_raw_mode(false)` 在每個退出路徑呼叫

若原始 `termios` 無法取得（`tcgetattr` 失敗），guard 不做任何事，避免將非 TTY stdin 誤設。
