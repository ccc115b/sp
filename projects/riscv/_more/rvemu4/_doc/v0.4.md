# rvemu4 v0.4 — RVC Decoder Overhaul: xv7 Boots Past `push_off`/`acquire`

A no-dependency RISC-V virtual machine in Rust (~1088 lines, 4 files).  
Supports RV32IMA + RV64GC, RVC, Sv39, multi-hart SMP (up to 8 harts),  
QEMU virt peripherals (UART 16550a, PLIC, CLINT, RTC, VIRTIO-BLK),  
and M-mode PMP CSRs.

Boots xv7 kernel past `main()` initialization including `push_off`/`acquire` spinlock
synchronization. Previously crashed at step ~257 due to corrupted stack frame.

## Build & Run

```bash
cargo build -r
./target/release/rvemu4 -kernel <kernel.elf> [-drive <disk.img>] [-smp <n>]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-kernel` | (required) | ELF32/ELF64 kernel loaded at 0x80000000 |
| `-drive` | none | Raw disk image for virtio-blk |
| `-smp` | 1 | Number of harts (1–8), all step in round-robin |

### RVC Decoder Bug Details

All six compressed memory-offset decoders had overlapping bit fields. Each term
extracted a range of instruction bits and shifted them to a position, but
different terms could extract the same instruction bits and map them to different
offset-bit positions, producing wrong offsets:

| Instruction | Old behavior | Correct behavior |
|-------------|-------------|-----------------|
| `c.sdsp ra, 24(sp)` (0xEC06) | Stored at sp+8 | Stores at sp+24 |
| `c.sdsp s0, 16(sp)` (0xE822) | Stored at sp+16 (correct by coincidence) | Stores at sp+16 |
| `c.sdsp s1, 8(sp)` (0xE426) | Stored at sp+24 | Stores at sp+8 |
| `c.ldsp ra, 24(sp)` (0x60E2) | Loaded from sp+4 (uninitialized memory) | Loads from sp+24 |
| `c.ldsp s0, 16(sp)` (0x6442) | Loaded from sp+2 | Loads from sp+16 |
| `c.ldsp s1, 8(sp)` (0x64A2) | Loaded from sp+8 (correct by coincidence) | Loads from sp+8 |
| `c.sw` / `c.sd` / `c.lw` / `c.ld` | Various overlapping offsets | Correct CL-type encoding |

#### Root Cause: `push_off` Stack Corruption

The kernel function `push_off` (called by `acquire`) saves registers with three
`c.sdsp` instructions:
```
sd ra, 24(sp)   → emulator stored at sp+8  (WRONG)
sd s0, 16(sp)   → emulator stored at sp+16 (correct)
sd s1, 8(sp)    → emulator stored at sp+24 (WRONG)
```

Later `push_off` restores with three `c.ldsp` instructions:
```
ld ra, 24(sp)   → loaded from sp+4  (WRONG — uninitialized)
ld s0, 16(sp)   → loaded from sp+2  (WRONG)
ld s1, 8(sp)    → loaded from sp+8  (got the saved ra)
```

The stores and loads used completely different offset formulas, so the saved
`ra` was never restored correctly. After `push_off` returned to `acquire`, the
corrupted `ra` caused a jump to garbage, crashing at step ~257.

### Fix Approach

Each decoder was rewritten to match the RISC-V specification's bit-field layout:

**CSS-type (c.swsp, c.sdsp):** offset is bits[12:7] as a 6-bit unsigned value:
```rust
let off = ((i >> 7) as u64 & 0x3F);
```

**CL-type (c.lw, c.ld, c.sw, c.sd):** offset eight bits mapped from instruction:
```rust
let off = ((i >> 6) & 1) << 7 | ((i >> 5) & 1) << 6 | ((i >> 12) & 1) << 5
        | ((i >> 11) & 1) << 4 | ((i >> 10) & 1) << 3
        | ((i >> 4) & 1) << 2 | ((i >> 3) & 1) << 1 | ((i >> 2) & 1);
```

**CI-type (c.lwsp):** offset bits mapped per spec:
```rust
let off = ((i >> 4) & 1) << 7 | ((i >> 5) & 1) << 6
        | ((i >> 12) & 1) << 5 | ((i >> 6) & 1) << 4
        | ((i >> 3) & 1) << 3 | ((i >> 2) & 1) << 2;
```

## xv7 Boot Status

The emulator now boots past the original crash point (`push_off`/`acquire` spinlock
synchronization in `main()`). The instruction trace confirms correct stack
restoration across hundreds of successive `acquire`/`push_off` calls during kernel
initialization (consoleinit → kinit → kvminit → ...).

The kernel continues executing millions of steps after the fix, but the PC
eventually reaches addresses beyond the loaded kernel image, suggesting a
remaining bug further in the boot sequence (possibly in S-mode trap handling
or user-process launch).

## Tested Programs

All [mini-riscv-os2](https://github.com/cccriscv/mini-riscv-os2) lessons 02–09
continue to pass (RV32/RV64, 1–4 harts).

## Known Limitations

- No D extension (floating point)
- AMO `.aq`/`.rl` ordering bits ignored (sequentially consistent)
- RTC returns wall-clock time (not deterministic)
- PMP registers accepted but not enforced
- UART LSR always reports THR empty (bit 6)
- Emulator may diverge late in xv7 boot (PC escapes kernel image)
- Exposes guest-level races (e.g. non-atomic `harts_ready++`)

## Bugs Fixed from v0.3

1. **C.J decoder bit layout** — computed offset -494 instead of -30 for `c.j pc-30`
   (funct3=5, quadrant 1)
2. **C.SDSP decoder (q=2, f3=7)** — overlapping bit fields; `sd ra, 24(sp)` stored at sp+8
3. **C.SWSP decoder (q=2, f3=6)** — same overlapping-bit-field pattern
4. **C.LWSP decoder (q=2, f3=2)** — overlapping bit fields in CI-type offset
5. **C.LW / C.LD / C.SW / C.SD (q=0, f3=2,3,6,7)** — all four CL-type decoders had overlapping bit fields
