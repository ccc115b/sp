# rvemu4 v0.10 — 全面單元測試覆蓋：131 項測試驗證 RV64GC 指令正確性

## 摘要

v0.9 雖可持續執行 xv6/xv7 超過 1.7B steps，但缺乏指令級測試覆蓋，除錯仰賴手動 trace。本版為**每一個 RV64 指令類別撰寫單元測試**，從 LUI/AUIPC 到 AMO LR/SC，含邊界案例（負數立即值、除法除零、溢位、CSR 特權行為等）。共 **131 項測試（原有 34 + 新增 97）全數通過**。同步清理主迴圈除錯輸出、加入 Ctrl+A → x 優雅退出、更新 AGENTS.md 為正確事實。

## 測試架構

### 編碼輔助函式

```rust
fn r_type(f7, rs2, rs1, f3, rd, opcode) -> u32
fn i_type(imm, rs1, f3, rd, opcode) -> u32
fn s_type(imm, rs2, rs1, f3, opcode) -> u32
fn b_type(imm, rs2, rs1, f3) -> u32
fn u_type(imm, rd, opcode) -> u32
fn j_type(imm, rd) -> u32
```

使用這些 helper 產生正確編碼，避免硬編碼 hex 造成的 rs1/rd 錯位（v0.10 修復多個此類測試編碼錯誤）。

### 執行輔助函式

- `exec_rv64(inst, regs, pc, is_64)` — 單步執行 32-bit 指令
- `exec_rvc(inst, regs, pc, is_64)` — 單步執行 16-bit 指令
- `exec_2(inst1, inst2, regs, is_64)` — 雙步執行（LR/SC、CSR 讀寫序列）

### 測試類別與數量

## 測試實作中發現與修復的 bug

本版本測試未修改模擬器核心邏輯，但 97 項新測試中有 9 項因測試編碼錯誤或期望值錯誤未通過：

| 測試 | 問題 | 修復 |
|------|------|------|
| `lui_negative` | 期望值 `0xFFFFFFFF80000000`（錯誤 32-bit sign-ext）→ 應為 `0xFFFFFFFFFF800000` | 更正為正確的 20-bit imm sign extension 結果 |
| `addiw_positive` | 期望值為 32-bit 未 sign-extended 值 | `0xFFFFFFFF80000000u64` |
| `mulhsu` | 期望 `(-1)*1` upper = 0（錯誤），正確為 `0xFFFFFFFFFFFFFFFF` | `assert_eq!(..., 0xFFFFFFFFFFFFFFFFu64)` |
| `sraw`/`sraiw` | 期望值缺少 64-bit sign extension | 改為 `0xFFFFFFFFF...000000u64` |
| `csrrs`/`csrrc` | 硬編碼 `0x300220F3` 的 rs1 欄位為 4 而非 2 | 改用 `i_type()` helper 產生正確編碼 |
| `sret_returns_to_sepc` | `mstatus` 設為 `0x200`（bit 9）而非 `0x100`（bit 8 SPP）| 修正 mstatus 初始值；SRET 依規範清除 SPP |
| `wfi_loops_when_mip_zero` | `check_interrupts` 在 WFI 執行前設定了 MTI 位元 | 設定 `clint.mtimecmp[0] = u64::MAX` |

## 除錯基礎設施改進

### STATE dump（替換 PROGRESS）

```
# v0.9: 每 1M steps
PROGRESS steps=1000K pc=0x8000080e

# v0.10: 每 50M steps
STATE steps=50M pc=0x8000080e sp=0x80008720 sepc=0x0 scause=0x0 priv=3 mip=0x800 mstatus=0x220 satp=0x0
```

提供更完整的除錯資訊，尤其是長時間執行後追蹤系統狀態變化。

### Ctrl+A → x 退出

在終端 raw mode 下，按 `Ctrl+A` 再按 `x` 即可優雅退出模擬器，無需 kill process。
