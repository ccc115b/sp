# rvemu4 v0.3 — RVC Bugfixes, PMP, xv6 Boot Progress

A no-dependency RISC-V virtual machine in Rust (~1070 lines, 4 files).  
Supports RV32IMA + RV64GC, RVC, Sv39, multi-hart SMP (up to 8 harts),  
QEMU virt peripherals (UART 16550a, PLIC, CLINT, RTC, VIRTIO-BLK),  
and M-mode PMP CSRs.

Boots xv6 from `_start()` through `main()` (enters S-mode via `mret`).  
Still debugging an infinite trap loop during `plicinithart`.

## Build & Run

```bash
cargo build -r
./target/release/rvemu4 -kernel <kernel.elf> [-drive <disk.img>] [-smp <n>]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-kernel` | (required) | ELF32/ELF64 kernel loaded at 0x80000000 |
| `-drive` | none | Raw disk image for virtio-blk |
| `-smp` | 1 | Number of harts (1–8), all step in round-robin |

## Architecture

```
0x00000000 ┌────────────────────────────┐
           │       ROM / unused         │
0x00101000 │ RTC (8 bytes, read-only)   │
0x02000000 │ CLINT (mtime + 8×mtimecmp) │
0x0C000000 │ PLIC (32 IRQs, 8 targets)  │
0x10000000 │ UART 16550a (8 registers)  │
0x10001000 │ VIRTIO-BLK (legacy)        │
0x80000000 │ DRAM (128 MB)              │
           └────────────────────────────┘
```

| Change | Detail |
|--------|--------|

| **Debug diagnostics** | JAL target/npc0, MRET target/priv/mstatus, TRAP cause/tval/priv printed to stderr |

### RVC Bugfix Details

Three bugs in the compressed-instruction decoder that prevented xv6 from booting:

1. **Quadrant 0 register swap** (lines 381–383): `rd_s` and `rs2_s` both used bits[4:2];
   `rs1_s` used bits[9:7]. Fixed to `rd_s = bits[4:2]+8`, `rs1_s = bits[9:7]+8`,
   `rs2_s = bits[4:2]+8`, matching the RVC spec.

2. **Quadrant 1 f3=4 rewrite** (lines 445–473): The old handler only supported C.SRLI.
   Replaced with a full decoder using bits[12] as a selector:
   - bit[12]=0: C.SRLI (f2=0), C.SRAI (f2=1), C.SUB (f2=2,fs=0), C.XOR (f2=2,fs=1),
     C.OR (f2=3,fs=2), C.AND (f2=3,fs=3)
   - bit[12]=1: C.ANDI (f2=1), C.SUBW (f3=3,fs=0), C.ADDW (f3=3,fs=1)

3. **C.LUI/C.ADDI/C.ADDIW/C.LI immediate field** (lines 422–443, various `imm` expressions):
   Changed `(i >> 7) & 0x1F` → `(i >> 2) & 0x1F` for the 5-bit immediate,
   combined with bit[12]→bit[5] via `| ((i as u64 >> 12) & 1) << 5`.

### PMP Support

Minimal — registers `pmpcfg0` and `pmpaddr0` exist in the CSR map but are
not enforced: M-mode accesses bypass all permission checks. xv6 programs
PMP to allow S-mode access; writes are accepted silently.

### xv6 Boot Status

xv6 now reaches `main()` in S-mode:
1. `_start` → `start()` → sets mstatus (MPP=S), mepc=main, delegates, PMP, timerinit
2. `mret` lands at `main()` — priv=1 (S-mode), mstatus=0x80
3. Main calls: consoleinit → printfinit → kinit → kvminit → kvminithart →
   procinit → trapinit → trapinithart → plicinit → **plicinithart** ← hangs here

The crash occurs in `plicinithart` after `cpuid` returns: PC jumps to 0x101000
(RTC MMIO address). The value read from RTC (0x8bc8/0x9f10) executes as an
illegal instruction. With `stvec=0` (xv6 hasn't set it yet), the trap handler
jumps to 0x0, then loops at 0x80007758 (data section). Investigation ongoing.

## Known Limitations

- No D extension (floating point)
- AMO `.aq`/`.rl` ordering bits ignored (sequentially consistent)
- RTC returns wall-clock time (not deterministic)
- PMP registers accepted but not enforced
- xv6 hangs during `plicinithart` (infinite trap loop)
- UART LSR always reports THR empty (bit 6)
- Exposes guest-level races (e.g. non-atomic `harts_ready++`)

## Bugs Fixed from v0.2

1. **Quadrant 0 rs1_s/rs2_s swap** → C.SW/C.SD used wrong base register
2. **RVC f3=4 Quadrant 1 too narrow** → only C.SRLI worked; added C.SUB, C.XOR, C.OR, C.AND, C.ANDI, C.SUBW, C.ADDW
3. **C.LUI/C.ADDI/C.ADDIW/C.LI wrong immediate** → used bits[9:7] instead of bits[4:2]+bit[12]
4. **Missing PMP CSRs** → read/write `pmpcfg0`/`pmpaddr0` (needed by xv6)
5. **No instruction trace** → added INST/JAL/MRET/TRAP debug output (conditional at instret < 10000)
