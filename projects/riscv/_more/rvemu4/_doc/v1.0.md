# rvemu4 v1.0 — xv6 完整開機至 Shell：VIRTIO 實體位址修正、DIVERGE 放寬、CR+LF 輸出

## 摘要

v0.10 雖有 131 項測試全數通過，但 xv6 執行至 `kexec("/init")` 時因 VIRTIO disk 讀回全零資料而卡死，最終因 DIVERGE 中止。本版定位並修復兩個致命錯誤：**VIRTIO `process_queue` 未將 Guest 實體位址轉換為 RAM 陣列索引**，以及 **DIVERGE PC 範圍檢查將合法的 trampoline 位址誤判為非法**。同步修正 UART 輸出缺少 CR 導致的階梯狀換行問題。**128MB RAM 下 xv6 可完整開機至 Shell 提示符號 `$ `。**

## 根因分析

### 問題 1：VIRTIO 描述子讀回全零（memory.rs）

xv6 的 `virtio_disk.c` 將實體位址（`kalloc()` 回傳值，如 `0x80012000`）寫入 VIRTIO MMIO register。`process_queue` 收到後使用 `r8(ram, addr)` 存取 `ram` Vec：

```rust
fn r8(ram: &[u8], a: u64) -> u8 {
    if a < ram.len() as u64 { ram[a as usize] } else { 0 }
}
```

`ram.len()` = 128MB = `0x800_0000`，而 `addr` = `0x8001_2000`。`0x8001_2000 < 0x800_0000` ❌ → 回傳 0。**所有描述子（descriptor table、avail ring、used ring）讀回全零**。

- 描述子 `addr` 欄位 = 0 → 資料緩衝區指向 RAM 開頭（kernel text）
- 描述子 `len` 欄位 = 0 → 讀取 0 bytes
- `kexec("/init")` 從 disk 讀入的 sector 資料全為 0 → init 無法執行 → process 1 exit → scheduler 永久迴圈

**修復**：每一處 `r8(ram, guest_addr)` 改為 `r8(ram, guest_addr - RAM_BASE)`，使 `0x8001_2000` 正確對應至 `ram[0x1_2000]`。

### 問題 2：DIVERGE 截斷 trampoline 執行（cpu.rs）

xv6 的 `uservec`（trap handler）位於虛擬位址 `0x3FFFFFF000`（trampoline 頁面，Sv39 最高位址）。當 user process 執行 `ecall` 觸發 trap 時：

```
ecall → pc = stvec = 0x3FFFFFF000 (uservec)
  → save registers → sfence.vma → jr kernelvec
```

舊的 DIVERGE 檢查 `pc > 0x88000000 || pc < 0x80000000` 將 `0x3FFFFFF09c` 判為非法，abort 並 dump 暫存器。

**修復**：檢查條件改為只攔截 `(0x88000000, 0x3FFFFFF000)` 的「無人地帶」，允許 kernel 範圍、trampoline 範圍與 user 範圍。

### 問題 3：UART 輸出階梯效應（memory.rs）

xv6 以 `\n`（LF）換行，raw mode 終端不會自動轉換為 CR+LF。結果每行從游標所在欄位開始，形成階梯狀：

```
xv6 kernel is booting
                     init: starting sh
                                      $
```

**修復**：UART THR write 收到 `b'\n'` 時先 flush `\r`（CR），將游標移回欄位 0。

## xv6 開機流程驗證

```
xv6 kernel is booting                  ← UART 初始化輸出
...（VIRTIO disk reads 完成）...
init: starting sh                      ← /init 程式執行
$                                      ← Shell 提示符號
```

透過 STATE dump 可追蹤關鍵里程碑：

```
STATE steps=100M pc=0x80000c8a   ← 早期初始化（尚未設定 stvec/satp）
STATE steps=500M pc=0x80001894   ← 已設定 Sv39 頁表與 kernel vec
STATE steps=1300M pc=0x80001888  ← Scheduler idle loop（等待中斷）
```

131 個單元測試全數通過，無回歸。

```bash
./run.sh          # 安靜執行（無 STATE 資訊、無 cargo 建置訊息）

```

## 剩餘已知問題

1. **MMU/Sv39 page walk** — 未經 real kernel 壓力測試
2. **無 D extension**（浮點）
3. **AMO `.aq`/`.rl` ordering bits 忽略**
4. **PMP registers 不強制執行**
5. **PLIC completion write 未實作** — 寫入 claim/complete register 被忽略，但不影響功能
