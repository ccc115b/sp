# rvemu4 v0.5 — C.ADDI16SP Bug 與 RVC Decoder 全面翻修

## 摘要

從 v0.4 的 RVC decoder 修正繼續前進，追蹤到 xv7 kernel 開機後期發散（PC 逃離 kernel image）的根本原因：**C.ADDI16SP decoder 計算錯誤的 immediate**，導致 sp 損毀、ra 載入錯誤位址。

同時合併 v0.4 中未 commit 的多項 RVC decoder 修正與除錯工具。

## 殘留的 C.ADDI16SP Bug

### 位置

`cpu.rs:456`，`exec_rvc` / quadrant 1 / funct3=3 / `rs1 == 2`：

```rust
let imm = Self::sext(((i >> 2) as u64 & 0x1F)
    | ((i >> 7) as u64 & 1) << 5
    | ((i >> 8) as u64 & 3) << 6
    | ((i >> 12) as u64 & 1) << 4, 9) as u64;
self.x[2] = self.x[2].wrapping_add(imm);
```

### 症狀

指令 `add sp, sp, 32`（編碼 0x6105，位於 xv7 kernel `acquire` epilogue 的 0x80000f92）:
- 正確: `sp += 32`
- 目前: `sp += 65`（junk immediate）

這讓 sp 從 0x80019791 跳到 0x800197d2（差 65 而非 32），導致後續 `ld ra, 24(sp)` 從錯誤位址載入 ra，最終 `ret` 跳到垃圾位址。

### 根因

C.ADDI16SP 的 immediate 編碼是 6-bit `nzuimm` 右移 4 位（×16 縮放）:
```
nzuimm[5] = inst[12]
nzuimm[4] = inst[6]
nzuimm[3] = inst[5]
nzuimm[2] = inst[4]
nzuimm[1] = inst[3]
nzuimm[0] = inst[2]
byte_offset = sext(nzuimm[5:0], 6) × 16
```

但現有實作從多個位元組（`inst[7]`, `inst[8:9]` 等）提取不存在的 immediate 位元，並以 `sext(…, 9)` 代替 `sext(…, 6) << 4`。

### 正確公式

```rust
let nzu = ((i >> 2) as u64 & 0x1F) | ((i as u64 >> 12) & 1) << 5;
let imm = Self::sext(nzu, 6) as u64 * 16;
if nzu != 0 { self.x[2] = self.x[2].wrapping_add(imm); }
```

## xv7 Boot Status

### 進展（v0.4 → v0.5）

- 已越過 `push_off`/`acquire` spinlock 同步點
- 執行數百萬步，歷經 `consoleinit` → `kinit` → `kvminit` → `kvmcreate` → `procinit` → `userinit`
- 最終發散點在 `acquire` epilogue，因 C.ADDI16SP 損毀 sp 而跳至 kernel image 外

### 修正後預期

C.ADDI16SP 修正後，推測 kernel 可完整開機至 shell。
