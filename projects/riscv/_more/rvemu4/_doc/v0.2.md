# rvemu4 v0.2 — Multi-Hart SMP + A Extension

A no-dependency RISC-V virtual machine in Rust (~1015 lines, 4 files).  
Supports RV32IMA + RV64GC, RVC, Sv39, multi-hart SMP (up to 8 harts),  
and QEMU virt peripherals (UART 16550a, PLIC, CLINT, RTC, VIRTIO-BLK).

Tested with [mini-riscv-os2](https://github.com/cccriscv/mini-riscv-os2) lessons 02–09,  
including multicore programs at 4 harts.

## Build & Run

```bash
cargo build -r
./target/release/rvemu4 -kernel <kernel.elf> [-drive <disk.img>] [-smp <n>]
```

| Flag | Default | Description |
|------|---------|-------------|
| `-kernel` | (required) | ELF32/ELF64 kernel loaded at 0x80000000 |
| `-drive` | none | Raw disk image for virtio-blk |
| `-smp` | 1 | Number of harts (1–8), all step in round-robin |

## Architecture Overview

```
0x00000000 ┌────────────────────────────┐
           │       ROM / unused         │
0x00101000 │ RTC (8 bytes, read-only)   │
0x02000000 │ CLINT (mtime + 8×mtimecmp) │
0x0C000000 │ PLIC (32 IRQs, 8 targets)  │
0x10000000 │ UART 16550a (8 registers)  │
0x10001000 │ VIRTIO-BLK (legacy)        │
0x80000000 │ DRAM (128 MB)              │
           └────────────────────────────┘
```

## What's New in v0.2

| Feature | Detail |
|---------|--------|
| **Multi-hart SMP** | Round-robin stepping of all harts (one instruction each per loop iteration) |
| **A extension** | All AMO operations + LR/SC with reservation tracking |
| **LR/SC reservation** | Per-hart `lr_reservations[8]` in Bus, cleared on conflicting stores |
| **Zero warnings** | All unnecessary parentheses, unused constants/fields removed |

### Multi-Hart SMP

- `main.rs` loop: step each hart once per iteration, poll stdin every 256 iterations
- Hart 0 is always the "boot hart" that runs `_start`
- CLINT provides independent `mtimecmp[hart]` per hart
- PLIC has per-hart interrupt enable/threshold registers
- Tested with `-smp 4` on 07-Multicore32bit and 08-Multicore64bit

### A Extension (AMO/LR/SC)

Implementations in `cpu.rs:334–355` (opcode 0x2F):

| Operation | f7[4:2] | Behavior |
|-----------|---------|----------|
| LR.W | 010 | Load word + set reservation at address |
| SC.W | 011 | If reservation matches, store & rd=0; else rd=1 |
| AMOSWAP | 001 | rd = old value, addr = rs2 |
| AMOADD | 000 | rd = old value, addr = old + rs2 |
| AMOXOR | 100 | rd = old value, addr = old ^ rs2 |
| AMOAND | 110 | rd = old value, addr = old & rs2 |
| AMOOR | 010 | rd = old value, addr = old | rs2 |
| AMOMIN/MINU/MAX/MAXU | 101/111 | Signed/unsigned min/max |

Reservation table (`memory.rs`):
- `Bus::lr_reservations: [Option<u64>; 8]` — `Some(addr)` or `None`
- `clear_reservations(addr)` called on every RAM `store8/16/32/64`

## CPU Core

### Decode/Execute
- `step()`: fetch via `vm_fetch()`, decode opcode, execute inline
- `wr!` macro: masks to `($v as u32) as u64` in RV32 mode
- Branch/SLT: uses `i32`/`u32` comparisons in RV32 mode

### RVC (Quadrants 0/1/2)
- Quadrant 0: C.ADDI4SPN, C.LW/C.LD/C.SW/C.SD
- Quadrant 1: C.ADDI/C.ADDIW/C.LI/C.LUI, shifts, J, B, ALU
- Quadrant 2: C.SLLI, C.LWSP/C.LDSP, jumps/links, C.SWSP/C.SDSP

### Sv39 MMU (`cpu.rs:95–125`)
- 3-level page walk (VPN[2]→PDE, VPN[1]→PDE, VPN[0]→PTE)
- A/D bit updates; permission: R, W, X, U, SUM bit
- Huge pages: 1 GiB (L2), 2 MiB (L1), 4 KiB (L0)

### CSR
| Group | Registers |
|-------|-----------|
| M-mode | mstatus, misa, medeleg, mideleg, mie, mtvec, mscratch, mepc, mcause, mtval, mip, mhartid, mcounteren, menvcfg |
| S-mode | sstatus, sie, stvec, sscratch, sepc, scause, stval, sip, satp, stimecmp |
| Read-only | time/cycle → `get_time_csr()`, instret |

### Traps
- `trap(cause, tval)`: saves PC/cause/tval, switches to M/S mode
- Delegation: medeleg/mideleg when `priv_level <= PRV_S`
- `mret`/`sret`: restore MPP/SPP from mstatus
- Priority: MEI > MSI > MTI > SEI > SSI > STI

## Device Models

### UART 16550a
- Output: `val as char` → stdout; Input: circular 256-byte RX buffer
- IER bit 0 enables RX interrupt; LSR bit 6 always set (THR empty)
- IRQ 10 routed from main loop via `plic.set_pending(10)`

### PLIC
- 32 sources × 8 targets; priority per source, enable/threshold per target
- Claim at 0x201000 + hart*0x2000 + 4 returns highest pending match
- `set_pending(irq)` raises; `claim` auto-clears

### CLINT
- `mtime` (0xBFF8, 8 bytes): `boot_time_ns() / 100` ≈ 10 MHz
- `mtimecmp[hart]` (0x4000 + hart*8): per-hart compare for M-mode timer
- `clint_has_mti(hart, now)` returns `mtimecmp[hart] <= now`

### VIRTIO-BLK
- Legacy interface: MMIO at 0x10001000
- Queue processing through descriptor chain (read/write from host file)

## Bugs Fixed from v0.1

1. **Single-hart only** → multi-hart round-robin stepping
2. **No LR/SC reservation** → `Bus.lr_reservations[8]` with cross-hart invalidation
3. **13 compiler warnings** → zero warnings (unnecessary parens, dead code, unused constants)
4. **Stuck detector noise** → removed from main loop

## Known Limitations

- No D extension (floating point)
- AMO `.aq`/`.rl` ordering bits ignored (sequentially consistent)
- RTC returns wall-clock time (not deterministic)
- UART LSR always reports THR empty (bit 6)
- Exposes guest-level races (e.g. non-atomic `harts_ready++`)
