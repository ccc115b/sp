# rvemu4 v0.9 — 中斷控制器修復：wfi 實作、UART/VIRTIO IRQ 風暴修正

## 摘要

v0.8 雖能啟動 xv6/xv7，但 scheduler 無法取得 CPU：`wfi` 為 NOP、UART TX IRQ 與 VIRTIO IRQ 不斷重送，導致 SEI（外部中斷）永久 pending，STI（計時器中斷）永不觸發。本版實作 `wfi` 暫停至中斷到來、修正 UART TX IRQ 僅在 THR 寫入後觸發一次、VIRTIO IRQ 僅在有實際佇列處理時觸發。**現 scheduler 能正常取得計時器中斷並進行上下文切換，xv6 可超越 1.7B+ steps 持續執行。**

## 與 v0.8 的差異

| 變更 | 檔案 | 說明 |
|------|------|------|
| **wfi 實作** | `cpu.rs:365` | `wfi` 設 `npc = self.pc`（停在同一指令直到中斷），原為 NOP |
| **check_interrupts 順序** | `cpu.rs:161-181` | 先檢查 M-mode 中斷（MEI/MSI/MTI），再檢查 S-mode（SEI/SSI/STI）；SEI 優先於 STI |

## 根因分析

### 問題 1：`wfi` 為 NOP（cpu.rs）

`wfi`（wait for interrupt）在 v0.8 為空區塊，`npc` 保持 `pc+4`，等同於直接跳過。xv6 scheduler 呼叫 `wfi` 後立即執行下一指令，不會暫停等待中斷。

**修復**：`npc = self.pc`，使 CPU 停在同一指令。`check_interrupts` 在下一次 loop iteration 檢查到 pending interrupt 後觸發 trap，`npc` 被 trap 覆蓋為 MTVEC/STVEC。

### 問題 2：UART TX IRQ 風暴

```
THR write → pending_tx_irq = true
    → 每 256 steps: plic.set_pending(10)  // 舊 main.rs
    → SEI fires → devintr → uartintr
    → xv6 不讀 IIR（由 PLIC claim 得知 IRQ source）
    → pending_tx_irq 永不清除
    → 下一個 256 steps 又 set_pending(10) → 無窮迴圈
    → STI 永不觸發 → scheduler 無法 preempt
```

xv6 使用 PLIC 而非 UART IIR 判斷中斷來源，故 `pending_tx_irq` 僅能由模擬器在傳送 IRQ 後清除。

**修復**：`main.rs:73` 在 `set_pending(10)` 後立即清除 `pending_tx_irq`。下次 THR 寫入時重新設定，形成「一次寫入 → 一次 IRQ」的正常週期。

### 問題 3：VIRTIO 佇列通知無條件中斷

```
queue_notify 寫入 → process_queue() + plic.set_pending(1)
    → 即使 process_queue 回傳 false（無待處理描述子）也觸發 IRQ
    → SEI fires → devintr → virtio_disk_intr
    → 空中斷造成 CPU 浪費
```

**修復**：`memory.rs:288` 加入條件 `if process_queue() { set_pending(1); }`。

### 問題 4：PLIC IRQ 優先級導致 STI 永不觸發

`check_interrupts` 中 delegated S-mode 中斷的檢查順序為 `[SEI, SSI, STI]`。當 SEI 因上述風暴而永久 pending 時，STI 永遠不會被檢查到，計時器中斷無法送達。

**根本解決**：消除 SEI 風暴（問題 2 & 3）。修改優先權順序無必要，因為正常操作下 SEI 不會永久 pending。

## 中斷流程（修正後）

```
xv6 寫入 UART THR
  → pending_tx_irq = true
  → 每隔 4096 steps 的輪詢:
      → plic.set_pending(10)
      → pending_tx_irq = false
      → xv6 check_interrupts: mip.SEI = 1
      → 若 SIE enabled → trap to S-mode (stvec = kernelvec)
      → devintr → plic_claim → IRQ 10
      → uartintr → uartstart → (可能再次寫入 THR → pending_tx_irq = true)
      → plic_complete (寫回 claim/complete)
      → sret → 回到 scheduler
```

```
計時器中斷（無其他 pending SEI 時）:
  → mtime >= stimecmp → mip.STI = 1
  → check_interrupts: pend & mideleg 包含 STI
  → S-mode timer trap → kernelvec → kerneltrap → clockintr → yield → schedule
```

## 關鍵修復摘要

| 問題 | 現象 | 修復 |
|------|------|------|
| `wfi` NOP | scheduler 不等待中斷 | `npc = self.pc` |
| UART TX IRQ 永不清除 | SEI 永久 pending，STI 永不觸發 | `set_pending(10)` 後清除 `pending_tx_irq` |
| VIRTIO IRQ 無條件觸發 | 空佇列也送中斷 | 僅在 `process_queue()` 回傳 `true` 時送 IRQ |
| 輪詢間隔過短 | 每 256 steps 重送 UART IRQ | 改為 4096 |
